# Aplicaciones AppUI

<p className="lead">
  Una aplicación AppUI describe sus ventanas en archivos <code>.fstui</code> (XML), escribe la lógica en
  una clase parcial y se dibuja con <code>std.ui</code>, un renderizador por software escrito en Faset.
  El mismo proyecto compila para Linux (X11) y Windows (Win32).
</p>

## Crear una aplicación

```bash
faset new MiApp --ui
cd MiApp
faset run
```

La plantilla genera tres archivos:

| Archivo | Contenido |
|---|---|
| `MainWindow.fstui` | La ventana y sus controles, en XML. Se edita a mano o con el [diseñador](/studio/disenador/). |
| `MainWindow.fst` | La otra mitad de `partial class MainWindow`: constructor, destructor y manejadores de eventos. |
| `Program.fst` | `Main`: crea la ventana y llama a `Application.Run`. |

```fst
// Program.fst
using std.ui;

namespace MiApp
{
    public static class Program
    {
        public static int Main()
        {
            auto window = new MainWindow();
            return Application.Run(window.Window);
        }
    }
}
```

## Cómo funciona

1. Al compilar, cada `.fstui` del proyecto se traduce a código Faset: una mitad de la clase parcial
   indicada en `Class`, con un campo `Widget` por cada control con `Name` y el método
   `InitializeComponent()`.
2. Tu código llama a `InitializeComponent()` en el constructor y responde a los eventos con métodos
   `void Nombre(Widget sender)`.
3. `Application.Run` abre la ventana nativa, procesa la entrada y redibuja cuando algo cambia.

Los errores del `.fstui` (atributos desconocidos, colores mal escritos, manejadores que no existen)
se muestran con la línea del XML, igual que los del código.

## El renderizador

`std.ui` dibuja cada píxel en un búfer en memoria (`Canvas`) y lo copia a la ventana:

- rectángulos redondeados con antialiasing, bordes, círculos y líneas;
- **degradados** verticales u horizontales en la ventana y en cada control;
- texto con FreeType (Linux) o GDI (Windows), con UTF-8 completo;
- temas oscuro y claro, foco visible con teclado, cursores según la zona;
- portapapeles del sistema en los cuadros de texto (`Ctrl+C`, `Ctrl+X`, `Ctrl+V`, `Ctrl+A`).

No depende de ninguna biblioteca de interfaz: en Linux solo enlaza `X11` y `freetype`; en Windows,
`user32` y `gdi32`. Las imágenes se decodifican con `stb_image`, incluido en `std.ui`. El `WebView`
(WebKitGTK) y el `VideoPlayer` (GStreamer) se cargan con `dlopen` solo si la ventana los usa.

## Controles

| Grupo | Controles | Página |
|---|---|---|
| Básicos | `Panel`, `Label`, `Button`, `TextBox`, `CheckBox`, `RadioButton`, `ComboBox`, `ListBox`, `Slider`, `ProgressBar` | [Formato .fstui](/ui/fstui/), [Colores y degradados](/ui/colores/) |

| Menús | `MenuBar` / `Menu` / `MenuItem` / `Separator`, `ContextMenu` | [Menús](/ui/menus/) |
| Dibujo y tiempo | `Canvas` (con `Graphics`), `Timer` | [Lienzo y temporizador](/ui/lienzo/) |
| Multimedia | `WebView`, `VideoPlayer`, `Sound`, `Music` | [WebView](/ui/webview/), [Vídeo y audio](/ui/multimedia/) |

`Timer`, `ContextMenu`, `Sound` y `Music` son **componentes**: van dentro de `<Window>` pero no se
dibujan. El ejemplo [`examples/controles`](https://github.com/MantraxStudios/Faset/tree/main/examples/controles)
usa menús, árbol, pestañas, imágenes, lienzo y temporizador en una sola ventana. Lo que todavía no
funciona en cada plataforma está en [Limitaciones de std.ui](/ui/limitaciones/).

## Capturas sin pantalla

Las aplicaciones `std.ui` pueden dibujarse sin abrir una ventana, útil para tests y para generar
capturas como las de esta documentación:

```bash
FASET_UI_SCREENSHOT=captura.bmp ./bin/Debug/linux-x86_64/MiApp
FASET_UI_SCREENSHOT=captura.bmp FASET_UI_SCRIPT="click 120 80 | type Hola | key tab" ./MiApp
```

`FASET_UI_SCRIPT` simula entrada antes de la captura: `click X Y`, `rclick X Y` (botón derecho),
`dblclick X Y`, `down X Y` / `up X Y` / `drag X Y`, `move X Y`, `scroll N`, `type texto`,
`key tab|enter|space|…` (también con modificadores: `key ctrl+s`, `key ctrl+shift+tab`, `key f5`),
`resize W H` y `wait MS`, separados por `|`. `wait` avanza el reloj de los `Timer` sin esperar de verdad.
