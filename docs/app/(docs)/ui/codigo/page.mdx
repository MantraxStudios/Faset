# Código de la ventana

<p className="lead">
  El <code>.fstui</code> y su <code>.fst</code> forman una sola clase parcial. El compilador escribe una
  mitad a partir del XML; tú escribes la otra.
</p>

## Lo que genera el compilador

Para `<Window Class="MainWindow" Namespace="MiApp">` con un botón `btnGreet`, la mitad generada
equivale, en esencia, a esto:

```fst
using std; using std.ui;
namespace MiApp
{
    public partial class MainWindow
    {
        public Window Window;          // la ventana
        Widget lblTitle;               // un campo por control con Name
        Widget btnGreet;

        void InitializeComponent() { /* crea la ventana y los controles, asigna atributos y eventos */ }
        static void __ui_event(void* self, Widget sender, int ev) { /* llama a OnGreetClick(sender)... */ }
    }
}
```

Casi todos los campos son `Widget`. Las excepciones: un `<VideoPlayer>` genera un campo
[`VideoPlayer`](/ui/multimedia/#videoplayer), un `<TreeNode>` con `Name` uno
[`TreeNode`](/ui/pestanas-y-arboles/#treeview-y-treenode), y `<Sound>`/`<Music>` campos `Sound` y `Music`
de [`std.audio`](/std/audio/) (en ese caso la mitad generada añade `using std.audio;`).

Los eventos se conectan con un [puntero a función](/lenguaje/delegados/) y un puntero a la instancia:
no hay reflexión ni asignaciones extra. El código generado mantiene las líneas del XML, así que los
errores de un manejador mal escrito apuntan a la línea correcta del `.fstui`.

## Tu mitad

```faset
using std.ui;

namespace MiApp
{
    public partial class MainWindow
    {
        int saludos;

        public MainWindow() { InitializeComponent(); }

        ~MainWindow() { delete Window; }               // la ventana libera sus controles

        void OnNameChanged(Widget sender)
        {
            string nombre = txtName.Text.Length > 0 ? txtName.Text : "Faset";
            lblTitle.Text = "Hola, " + nombre + (chkExcited.Checked ? "!" : "");
        }

        void OnVolumeChanged(Widget sender) { prgVolume.Value = sldVolume.Value; }

        void OnGreetClick(Widget sender)
        {
            saludos++;
            btnGreet.Enabled = saludos < 3;
        }

        void OnCloseClick(Widget sender) { Window.Close(); }
    }
}
```

## API más usada de `Widget`

| Miembro | Descripción |
|---|---|
| `Text` | Texto (get/set). Al asignarlo, el control hace su propia copia. |
| `Placeholder` | Texto de ayuda de un `TextBox` vacío. |
| `Checked` | Estado de `CheckBox` y `RadioButton`. |
| `Value`, `Min`, `Max`, `Fraction` | Valor de `Slider` y `ProgressBar`. |
| `SelectedIndex`, `SelectedItem` | Selección de `ComboBox` y `ListBox`. |
| `SetItems("a;b;c")`, `AddItem`, `RemoveItemAt`, `ClearItems`, `Item(i)`, `ItemCount` | Elementos de las listas. |
| `Enabled`, `Visible` | Estado. |
| `X`, `Y`, `Width`, `Height`, `Anchor` | Disposición. |
| `Background`, `Background2`, `GradientHorizontal`, `Foreground`, `BorderColor`, `Accent` | Colores (ver [Colores y degradados](/ui/colores/)). |
| `Tag` | `void*` libre para tus datos. |
| `Source`, `SizeMode`, `Image`, `Icon` | Imágenes de `PictureBox`, `Button` y `MenuItem` (ver [Imágenes](/ui/imagenes/)); `Source` también navega en un `WebView`. |
| `SelectedPage`, `AddPage`, `Nodes`, `AddNode`, `SelectedNode` | `TabControl` y `TreeView` (ver [Pestañas y árboles](/ui/pestanas-y-arboles/)). |
| `Shortcut`, `AddMenuItem`, `ContextMenu`, `SourceControl` | Menús (ver [Menús](/ui/menus/)). |
| `Interval`, `Start()`, `Stop()` | `Timer` (ver [Lienzo y temporizador](/ui/lienzo/)). |
| `Invalidate()` | Pide redibujar el control (un `Canvas` vuelve a llamar a `Paint`). |
| `ActualWidth`, `ActualHeight` | Tamaño real tras aplicar los anclajes. |

## API más usada de `Window`

| Miembro | Descripción |
|---|---|
| `Title` | Título (get/set, UTF-8). |
| `Theme` | `UiTheme.Dark` o `UiTheme.Light`. |
| `Find("nombre")` | Busca un control por nombre. |
| `Focus(widget)` | Mueve el foco del teclado. |
| `Close()` | Cierra la ventana; `Application.Run` devuelve. |
| `Add(widget)` | Añade un control creado a mano con `Widget.Create`. |
| `AddComponent(widget)`, `FindComponent("nombre")`, `Components` | Componentes (`Timer`, `ContextMenu`). |
| `ShowContextMenu(menu, x, y)`, `CloseMenus()` | Menús contextuales desde el código. |

La referencia completa, extraída del código fuente, está en [`std.ui`](/std/ui/).

## Eventos con lambdas

Todos los controles tienen los [eventos](/lenguaje/eventos/) `Click` y `Changed` (y los `Timer`,
`Tick`), de tipo `Action<Widget>`: se pueden suscribir lambdas desde el código, además de los
manejadores del `.fstui`, sin `memory_unsafe`:

```faset
using std.ui;

class Demo
{
    public Window Window = new Window("Lambdas", 320, 140);
    int segundos;

    public Demo()
    {
        var lbl = Window.Add(Widget.Create(WidgetKind.Label, "lbl", 20, 20, 280, 24));
        var btn = Window.Add(Widget.Create(WidgetKind.Button, "btn", 20, 60, 140, 32));
        var reloj = Window.AddComponent(Widget.Create(WidgetKind.Timer, "reloj", 0, 0, 0, 0));
        btn.Text = "Reiniciar";
        btn.Click += s => segundos = 0;
        reloj.Interval = 1000;
        reloj.Tick += s => {
            segundos++;
            lbl.Text = "Segundos: " + segundos;
        };
        reloj.Start();
    }
}

int main()
{
    var d = new Demo();
    return Application.Run(d.Window);
}
```

## Manejadores async

Un manejador puede ser `async void` y esperar sin bloquear la ventana. `Window.Run` instala un
contexto de sincronización en el hilo de la interfaz, así que después de cada `await` el método
sigue en ese hilo y puede tocar los controles (ver [async y await](/lenguaje/async/)):

```fst
async void OnDescargar(Widget sender)
{
    btnDescargar.Enabled = false;
    lblEstado.Text = "Descargando...";
    string html = await http.GetStringAsync("https://example.com/");   // la ventana sigue respondiendo
    lblEstado.Text = "Recibidos " + html.Length + " bytes";
    btnDescargar.Enabled = true;
}
```

Sin pantalla (`FASET_UI_SCREENSHOT`), el verbo `wait MS` del guion de pruebas ejecuta también las
continuaciones que llegan durante la espera.

## Conectar eventos a mano

Los controles creados con `Widget.Create` no tienen eventos hasta que les das una función y un número
por evento, que es justo lo que hace el código generado. `SetEvents(funcion, objeto, click, changed)`
fija la función (un [puntero a función](/lenguaje/delegados/) estático que recibe el objeto como
`void*`) y los números de `Click` y `Changed`; `SetEvent(WidgetEvent.X, numero)` añade el resto
(`SelectedChanged`, `NodeActivated`, `Paint`, `MouseDown`, `MouseMove`, `MouseUp`, `Tick`). Como usa
`void*`, va en un bloque `memory_unsafe`:

```faset
using std.ui;

class Demo
{
    public Window Window = new Window("Eventos a mano", 420, 260);
    Widget lienzo;
    Widget reloj;
    int ticks;

    memory_unsafe static void Evento(void* self, Widget sender, int ev) { ((Demo)self).OnEvento(sender, ev); }

    void OnEvento(Widget sender, int ev)
    {
        if (ev == 1) { ticks++; lienzo.Invalidate(); }                        // Tick
        if (ev == 2)                                                          // Paint
        {
            Graphics g = sender.Graphics;
            g.Clear(Rgb.Of(0x101018));
            g.FillCircle(40 + ticks % 300, 100, 20, Rgb.Of(0x4c8dff));
        }
        if (ev == 3) println("clic en " + sender.Mouse.X + ", " + sender.Mouse.Y);  // MouseDown
    }

    public Demo()
    {
        lienzo = Window.Add(Widget.Create(WidgetKind.Canvas, "lienzo", 10, 10, 400, 240));
        reloj = Window.AddComponent(Widget.Create(WidgetKind.Timer, "reloj", 0, 0, 0, 0));
        reloj.Interval = 16;
        memory_unsafe
        {
            lienzo.SetEvents(&Evento, (void*)this, 0, 0);
            lienzo.SetEvent(WidgetEvent.Paint, 2);
            lienzo.SetEvent(WidgetEvent.MouseDown, 3);
            reloj.SetEvents(&Evento, (void*)this, 0, 0);
            reloj.SetEvent(WidgetEvent.Tick, 1);
        }
        reloj.Start();
    }
}

int main()
{
    auto demo = new Demo();
    return Application.Run(demo.Window);
}
```

Durante `Paint`, `sender.Graphics` es el contexto de dibujo; durante un evento de ratón, `sender.Mouse`
tiene el último `MouseArgs`. Un `WebView` usa además `SetWebEvents(navigated, titleChanged, message)` y
un `VideoPlayer`, su propio `SetEvents(funcion, objeto, opened, ended, failed)`.

## Varias ventanas

Cada `.fstui` define su propia clase, así que una aplicación puede tener varias (`MainWindow.fstui`,
`Ajustes.fstui`…). Crea la instancia y ejecútala con `Application.Run(ventana.Window)`.
