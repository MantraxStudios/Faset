# Biblioteca estándar

<p className="lead">

## Cómo se cargan los módulos

`std` (el núcleo) se importa siempre. El resto se carga automáticamente al importarlo o al usarlo
con su nombre completo:

```faset
using std.collections;              // estilo C#
using namespace std::io;            // estilo C++
import std.text;                    // también vale

int main()
{
    auto l = new List<int>();       // de std.collections
    println(std::io::File::Exists("no-existe.txt"));   // nombre totalmente cualificado
    return 0;
}
```

## Seguridad

Toda la biblioteca está escrita como **envoltorios seguros**: las clases que usan punteros o llaman al
runtime en C están marcadas `memory_unsafe` (implementación confiable), pero su API pública no usa
punteros, así que `List<T>`, `StringBuilder`, `File`, `HttpClient` o `Mutex` se usan desde código
normal. La biblioteca no tiene privilegios especiales: cumple las mismas reglas que tu código.

## Propiedad de la memoria

La memoria la gestiona el [recolector de basura](/lenguaje/memoria/): nada de lo que devuelve la
biblioteca hay que liberarlo. La documentación de cada función sigue diciendo si devuelve una copia
o una vista, porque influye en el rendimiento:

- **Copias nuevas** — `String.Concat`, `ToUpper`, `Text.Join`, `Convert.ToString`,
  `File.ReadAllText`, `Dictionary.Keys()`… Reservan memoria del recolector, que la recupera cuando
  deja de usarse.
- **Vistas** — `Substring`, `Trim`, `Text.Split` (sus partes), `StringBuilder.View()`,
  `Path.GetFileName`… No copian nada: apuntan a la cadena original y la mantienen viva.
- **Recursos** — las clases que poseen algo del sistema (`FileStream`, `TcpClient`, `Process`,
  `Window`, `ThreadPool`…) lo cierran en su destructor. `delete` lo cierra en ese momento; si no lo
  haces, se cierra cuando el recolector recupera el objeto.

`String.Free` y `delete` de una colección siguen compilando, pero ya no hacen falta.

## Añadir tus propios módulos

Crea `lib/<raíz>/<módulo>.fst`; `using raíz.módulo;` lo cargará. Por ejemplo,
`lib/juego/fisica.fst` con `namespace juego.fisica { ... }` se usa con `using juego.fisica;`.

<Callout type="nota">
Las páginas de cada módulo se generan con `docs/scripts/extract-api.mjs`, que lee los miembros
públicos y sus comentarios `//`. Cualquier módulo nuevo de `lib/std` aparece aquí automáticamente. Los
miembros con la etiqueta `memory_unsafe` (punteros en la firma o marcados así) solo se usan dentro de
un contexto [`memory_unsafe`](/lenguaje/seguridad-de-memoria/).
</Callout>
