# Proyectos `.fstproj`

<p className="lead">
  Un <code>.fstproj</code> es un XML al estilo de los <code>.csproj</code> de .NET SDK. Todos los
  <code>.fst</code> y <code>.fstui</code> de su carpeta (y subcarpetas) se compilan automáticamente.
</p>

```fstproj
<Project>
  <PropertyGroup>
    <OutputType>Exe</OutputType>             <!-- Exe | WinExe | Library -->
    <AssemblyName>MiApp</AssemblyName>
    <TargetPlatform>native</TargetPlatform>  <!-- native | linux | windows | android -->
    <TargetArch>x86_64</TargetArch>          <!-- x86_64 | x86 | arm64 | armv7 -->
    <Configuration>Debug</Configuration>     <!-- Debug | Release -->
    <StaticLink>false</StaticLink>
  </PropertyGroup>
  <ItemGroup>
    <Compile Remove="experimentos/**" />                         <!-- excluir archivos -->
    <Compile Include="../compartido/*.fst" />                    <!-- añadir archivos -->
    <ProjectReference Include="../Utilidades/Utilidades.fstproj" />
    <NativeLibrary Include="user32" Platform="windows" />        <!-- -luser32 solo en Windows -->
    <LibraryPath Include="libs" />                               <!-- -Llibs -->
    <Asset Include="sonidos/**" />                               <!-- recursos junto al ejecutable / en el APK -->
    <PackageReference Include="Json5" Git="https://github.com/usuario/json5-faset" Version="^1.2" />
  </ItemGroup>
</Project>
```

## Propiedades (`PropertyGroup`)

| Propiedad | Valores | Efecto |
|---|---|---|
| `OutputType` | `Exe` (por defecto), `WinExe`, `Library` | `WinExe` = aplicación de ventana sin consola en Windows (`--gui`); `Library` = biblioteca compartida (`--shared`). |
| `AssemblyName` | nombre | Nombre del ejecutable. Por defecto, el del `.fstproj`. |
| `TargetPlatform` | `native`, `linux`, `windows`, `android` | Plataforma de destino; `native` es la de la máquina. Se puede cambiar con `--target`. |
| `TargetArch` | `x86_64`, `x86`, `arm64`, `armv7` | Arquitectura. Por defecto, la de la máquina (o `arm64` en Android). |
| `AndroidApi` | número | Nivel de API de Android (por defecto 24). |
| `Configuration` | `Debug`, `Release` | `Debug` compila con `-O0 -g`; `Release` con `-O2`. Se cambia con `-c`. |
| `OutputPath` | ruta | Carpeta raíz de la salida (por defecto `bin`). |
| `StaticLink` | `true` / `false` | Enlazado estático (`-static`). |
| `RuntimeChecks` | `true` / `false` | [Diagnósticos de Debug](/lenguaje/seguridad-de-memoria/#diagnosticos-de-debug) (uso después de `delete`, `delete` doble); por defecto, solo en `Debug`. Las comprobaciones de nulos, índices y divisiones están siempre activas. |
| `AllowUnsafe` | `true` / `false` | Todo el proyecto es un contexto `memory_unsafe` (como `--allow-unsafe`). |
| `AndroidPackage`, `AppName`, `VersionCode`, `VersionName`, `AndroidTargetSdk`, `AndroidAbis`, `AndroidOrientation`, `AndroidIcon`, `AndroidKeystore`, `AndroidKeyAlias` | texto | Empaquetado del APK: consulta [Android](/android/#propiedades-del-fstproj). |
| `EnableDefaultCompileItems` | `true` / `false` | Con `false` solo se compilan los archivos indicados con `Compile Include`. |
| `PackageId`, `Version`, `Description`, `Authors`, `License`, `RepositoryUrl` | texto | Metadatos de un [paquete](/empezar/paquetes/#crear-y-publicar-un-paquete): `PackageId` es su nombre y `Version` (semver) la versión que se publica con la etiqueta `vX.Y.Z`. `faset pack` los comprueba. |
| `PackageIndex` | URL o ruta | [Índice de paquetes](/empezar/paquetes/#el-indice-de-paquetes) donde se buscan los `<PackageReference>` sin `Git` ni `Path` (por defecto `https://faset.lat/paquetes/index.json`). |
| `RootNamespace`, `Optimize`, `DebugSymbols` | texto | Se aceptan como metadatos; el compilador todavía no los usa. |

<Callout type="aviso">
Las propiedades y elementos desconocidos **dan error**: así una errata (`<Configuraton>`) no pasa
desapercibida.
</Callout>

## Elementos (`ItemGroup`)

| Elemento | Atributos | Efecto |
|---|---|---|
| `Compile` | `Include`, `Remove` | Añade o excluye archivos. Admite comodines (`*`, `**`) y listas separadas por `;`. |
| `ProjectReference` | `Include` | Referencia a otro proyecto, que debe ser `Library`. Sus archivos se compilan junto con el tuyo. |
| `NativeLibrary` | `Include`, `Platform` (opcional) | Biblioteca nativa a enlazar (`-l`). Con `Platform` solo se usa para ese objetivo. |
| `LibraryPath` | `Include` | Carpeta de bibliotecas nativas (`-L`), relativa al proyecto. |
| `AndroidPermission` | `Include` | Permisos de Android (`INTERNET;CAMERA` → `android.permission.*`); se heredan de las bibliotecas referenciadas. |
| `Asset` | `Include`, `Remove` | Recursos que el programa lee en ejecución (sonidos, imágenes, vídeos, datos). Ver [Recursos](#recursos-asset). |
| `PackageReference` | `Include`, `Version`, `Git`, `Branch`, `Commit`, `Path`, `Folder` | Paquete (una biblioteca Faset) de un repositorio git, una carpeta o el índice. Se descarga a la caché, se fija en `paquetes.lock` y se compila como un `ProjectReference`. Ver [Paquetes](/empezar/paquetes/). |

## Recursos (`<Asset>`)

`<Asset Include="..."/>` declara archivos que el programa abre en ejecución. Al compilar se copian
**junto al ejecutable** (escritorio) o a **`assets/` dentro del APK** (Android), conservando la ruta
relativa al proyecto:

```fstproj
<ItemGroup>
  <Asset Include="sonidos/*.wav" />          <!-- comodines: * y ** -->
  <Asset Include="niveles" />                <!-- una carpeta incluye todo lo que contiene -->
  <Asset Include="datos/config.json;datos/textos.json" />
  <Asset Include="video/**" Remove="video/borradores/**" />
</ItemGroup>
```

```text
MiJuego/sonidos/clic.wav  →  bin/Debug/linux-x86_64/sonidos/clic.wav
                          →  MiJuego.apk: assets/sonidos/clic.wav
```

En escritorio solo se copian los archivos que han cambiado. Un `Include` que nombra un archivo que no
existe es un error de compilación. En el APK los recursos van sin comprimir, así Android los puede leer
directamente.

### Cómo se resuelven las rutas relativas

`Sound.Load`, `Music.Load`, `Image.FromFile`, `PictureBox.Source` y `VideoPlayer.Source` buscan una ruta
relativa (`sonidos/clic.wav`), por orden:

1. en la **carpeta actual**;
2. **junto al ejecutable** (donde `<Asset>` la copió);
3. en Android, **dentro del APK** (`assets/sonidos/clic.wav`).

Así el programa encuentra sus archivos se ejecute desde donde se ejecute. Las funciones de
[`std.io`](/std/io/) (`File.ReadAllText`…) solo usan la carpeta actual; en Android, esa carpeta es el
almacenamiento interno de la app, no el APK.

### Lo que se copia sin `<Asset>`

En un programa que usa `std.ui`, el compilador copia también (y empaqueta en el APK) **la carpeta
`Assets/` del proyecto** y **los archivos que nombran los `.fstui`** con `Source` o `Icon`: imágenes de
`PictureBox`, iconos, vídeos de `VideoPlayer` y sonidos de `<Sound>`/`<Music>`. `<Asset>` hace falta
para lo que solo se carga desde el código, y para cualquier recurso de un programa sin `std.ui`.

## Qué archivos se compilan

- Todos los `.fst` y `.fstui` bajo la carpeta del proyecto.
- Se ignoran `bin/`, `obj/`, las carpetas ocultas y las subcarpetas que tienen su propio `.fstproj`.
- Las referencias circulares entre proyectos se detectan y dan error.

## Referencias entre proyectos

```text
examples/proyecto/
├── MiJuego/
│   ├── MiJuego.fstproj      ← Exe, referencia a ../Utilidades
│   ├── Program.fst
│   └── Motor/Entidad.fst
└── Utilidades/
    ├── Utilidades.fstproj   ← Library
    └── Biblioteca.fst
```

```bash
faset run examples/proyecto/MiJuego
```

Una biblioteca referenciada no se enlaza como `.so` aparte: como las plantillas se instancian por tipo,
su código se compila **dentro** del programa que la usa, y sus `NativeLibrary`, `LibraryPath` y
`AndroidPermission` se heredan. Las bibliotecas pueden referenciar otras: se detectan los ciclos y cada
una se incluye una sola vez aunque llegue por varios caminos. El resultado es un único binario (o una
única `lib<App>.so` en el APK). Para producir una biblioteca dinámica
independiente, compila el proyecto `Library` por sí solo (genera `libNombre.so` o `Nombre.dll`).

Para usar bibliotecas de otros repositorios (con versiones, dependencias transitivas y
`paquetes.lock`) usa [`<PackageReference>`](/empezar/paquetes/) en lugar de copiar la carpeta.

## Soluciones (`.fstp`)

Una **solución** agrupa varios proyectos, como el `.sln` de Visual Studio: se compilan juntos en el
orden de sus `<ProjectReference>` y se ejecuta el **proyecto de inicio**.

```xml
<Solution Name="MiJuego">
  <Folder Name="Bibliotecas">
    <Project Path="Utilidades/Utilidades.fstproj" />
  </Folder>
  <Project Path="Juego/Juego.fstproj" Startup="true" />
</Solution>
```

- `Path` es relativo al `.fstp`; `<Folder>` (anidable) solo organiza el explorador.
- `Startup="true"` marca el proyecto que ejecuta `faset run` (si no hay, el primer `Exe`/`WinExe`).
- `<Solution>` admite `Configuration` y `TargetPlatform` por defecto para toda la solución.

```bash
faset new sln MiJuego                 # MiJuego/MiJuego.fstp vacía
faset new MiJuego --solution          # solución + un proyecto de consola dentro
faset sln add Motor/Motor.fstproj --folder Bibliotecas
faset sln ref Juego Motor             # <ProjectReference> de Juego a la biblioteca Motor
faset sln startup Juego
faset sln list                        # proyectos, carpetas y proyecto de inicio (--json)
faset build MiJuego.fstp              # todos, en orden de dependencias
faset run                             # en una carpeta con un .fstp: compila todo y ejecuta el de inicio
```

`faset sln help` muestra todas las órdenes (`remove`, `folder`, `move`, `rename`...). Si una
biblioteca falla, los proyectos que dependen de ella se saltan y se indica al final.

### En FasetStudio

Archivo → Abrir acepta un `.fstp` (y una carpeta con uno se abre como solución). El explorador muestra
«Solución 'MiJuego' (N proyectos)» con sus carpetas y proyectos; el de inicio va en negrita. Con el
botón derecho se agregan proyectos nuevos o existentes, carpetas y referencias, se elige el proyecto
de inicio o se compila uno solo. <Kbd>Ctrl+B</Kbd> y <Kbd>F5</Kbd> compilan toda la solución. En el
diálogo de proyecto nuevo, **Crear una solución** genera `Nombre/Nombre.fstp` con el proyecto dentro.
El IntelliSense analiza cada archivo con su propio proyecto y llega (<Kbd>F12</Kbd>) a las
bibliotecas referenciadas.

## Bibliotecas que enlaza el compilador por ti

Si un programa usa `std.ui`, `faset` añade automáticamente `X11` y `freetype` (Linux), `user32` y
`gdi32` (Windows) o `android` y `log` (Android); si además usa un `WebView`, en Android añade el permiso
`INTERNET`. `std.audio` añade `winmm` en Windows y `OpenSLES` en Android; en Linux, PulseAudio, ALSA,
WebKitGTK y GStreamer se cargan con `dlopen` y no hace falta enlazarlos. `std.net` añade `ws2_32` en Windows y `std.thread`
añade `pthread` en Linux. Siempre se enlaza `libm`.
