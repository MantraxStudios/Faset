# Limitaciones actuales

<p className="lead">
  Faset 0.2 es joven. Esta es la lista honesta de lo que el compilador rechaza hoy, con el mensaje que
  verás y la alternativa recomendada.
</p>

| No disponible | Alternativa |
|---|---|
| Herencia de varias clases | Una clase base y [varias interfaces](/lenguaje/interfaces/) |
| *Boxing* (convertir `int`, `string` o un struct a `object` o a una interfaz) | Un tipo envoltorio o un [registro](/lenguaje/registros/) `record class` |
| Expresiones `throw` (`x ?? throw ...`) | Una instrucción `throw` (las [excepciones](/lenguaje/excepciones/) sí existen) |
| Parámetros con valor por defecto | Sobrecargas (o [`params`](/lenguaje/comodidades/#params)) |
| `Console.WriteLine(tupla)` (no hay *boxing*) | `Console.WriteLine($"{tupla}")` |
| Inicializadores de objeto `new T { X = 1 }` | Constructores |
| Tipos anidados | Tipos en el mismo namespace |
| `using static` | Nombre de la clase delante (`Math.Sqrt`) |
| `goto`, `stackalloc`, `fixed` | — |
| Covarianza de arreglos (`string[]` como `object[]`) y arreglos de más de 3 dimensiones | Un [arreglo](/lenguaje/arreglos/) nuevo (`Array.ConvertAll`) o un arreglo escalonado |
| Operadores compuestos sobre la propiedad de un struct temporal (`F().X += 1`) | Guardar el struct en una variable |
| `await` en la condición o el incremento de un `for`, en la condición de un `do`-`while`, dentro de `?.`/`??=` o en un filtro `when` | `var x = await ...;` antes (ver [async y await](/lenguaje/async/)) |
| `ValueTask`, métodos `async` o iteradores en un `struct` o con parámetros `ref`/`out` | `Task<T>`, una clase o un método estático |
| `IEnumerable`/`IEnumerator` no genéricos, `Reset()`, `IDisposable`, `[EnumeratorCancellation]` | `IEnumerable<T>`; `Dispose()` está en `IEnumerator<T>`; el token como argumento |
| `yield` en una lambda sin tipo de delegado conocido; funciones locales genéricas, con `ref`/`out` o llamadas antes de declararse | Una [función local](/lenguaje/iteradores/#funciones-locales) declarada antes de usarla |

## Otras notas

- Lambdas y delegados: los delegados son estructurales (`Predicate<int>` y `Func<int, bool>` son el
  mismo tipo); un `delegate` declarado dentro de una clase se usa por su nombre simple (no
  `Clase.Delegado`) y no puede usar los parámetros de tipo de una clase genérica. Los métodos LINQ
  propios de `List<T>` (`lista.Where(...)`) son inmediatos; los de `IEnumerable<T>` son perezosos
  como en C# (ver [LINQ](/lenguaje/linq/#dos-versiones-inmediata-en-listt-perezosa-en-ienumerablet)).
  `Distinct`/`GroupBy`/`ToDictionary` necesitan claves con `Hash.Of` (números, `char`, `bool`,
  `string`).
- Un struct no se puede usar como `IEnumerable<T>` (no hay *boxing*); `string` sí (se convierte en un
  `IEnumerable<char>` que recorre sus caracteres).

- No hay literales octales: `0777` es decimal (como en C#); usa `0x1FF`.
- El [orden de evaluación](/lenguaje/operadores/#orden-de-evaluación) es el de C#, salvo en la
  deconstrucción `(a[i], b) = (x, y)`: los destinos se calculan después del lado derecho. Una
  referencia `T&` que apunta a un campo y ese mismo campo, usados en una misma expresión con
  efectos, tampoco se ordenan.
- Una carrera de datos sobre una misma variable `string` (dos hilos escribiéndola sin cerrojo) puede
  dejar una cadena a medio escribir, y el código `memory_unsafe` no se comprueba; consulta lo que
  [no cubre la seguridad de memoria](/lenguaje/seguridad-de-memoria/#lo-que-no-cubre).
- El recolector de basura es conservador y no mueve los objetos: un valor entero que por casualidad
  parezca una dirección del heap puede mantener vivo un bloque que ya no se usa.
- Los bindings de Win32 y de Android más allá de `std.ui` no vienen incluidos: se declaran con
  `extern` dentro de código `memory_unsafe`.
- `std.thread` y `std.net` en Windows suponen x86-64/ARM64 (los `extern` no declaran `__stdcall`).
  Varios hilos que escriben con `println` a la vez pueden intercalar líneas: protégelo con un `Mutex`.
- `std.net` no tiene proxies, compresión ni keep-alive.
- [async y await](/lenguaje/async/): la E/S asíncrona de red y de archivos (`GetStringAsync`,
  `ReadAllTextAsync`, `ConnectAsync`...) corre en hilos del grupo de tareas con llamadas bloqueantes
  (no hay un reactor con `epoll`/IOCP), así que miles de operaciones de red simultáneas ocupan
  muchos hilos; `Task.Delay` sí usa un único hilo de temporizadores. En `x += await f()` se lee `x`
  después de esperar (C# lo lee antes). `async void` no guarda las excepciones: si nadie las atrapa,
  terminan el programa. Esperar bloqueando (`.Result`, `.Wait()`) en el hilo de la interfaz a una
  tarea que necesita volver a él lo bloquea para siempre (como en C#).
- Android: `std.ui` no conoce los recortes de la pantalla (la barra de navegación se dibuja encima)
  ni redimensiona la ventana cuando aparece el teclado. Consulta [Android](/android/#limitaciones).
- FasetStudio funciona en Linux (X11/XWayland) y Windows (compilado pero aún sin probar en un Windows
  real; probado con Wine); las aplicaciones `std.ui` funcionan en Linux, Windows
  y Android.
