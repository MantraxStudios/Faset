# Punteros e interoperabilidad con C

<p className="lead">
  Faset compila a C, así que llamar a C no necesita envoltorios ni <em>marshalling</em>: cualquier función
  de C, de una DLL de Windows o del NDK de Android se declara con <code>extern</code> y se llama directamente.
  Los punteros y las llamadas nativas viven dentro de contextos <code>memory_unsafe</code>.
</p>

<Callout type="nota">
Faset es seguro por defecto: los tipos puntero, `&x`, `*p`, `p->x`, `p[i]`, la aritmética de
punteros y las llamadas a funciones `extern` solo se permiten en un contexto `memory_unsafe` (un
bloque, un método, una clase, un namespace o el archivo entero). Consulta
[Seguridad de memoria](/lenguaje/seguridad-de-memoria/).
</Callout>

## Punteros

```faset
memory_unsafe void Intercambiar(int* a, int* b)
{
    int t = *a;
    *a = *b;
    *b = t;
}

int main()
{
    int x = 1, y = 2;
    memory_unsafe
    {
        Intercambiar(&x, &y);
        long* nums = new long[10];
        for (int i = 0; i < 10; i++) nums[i] = (long)i * i;
        long total = 0;
        for (long* p = nums; p < nums + 10; p++) total += *p;   // aritmética de punteros
        println(total);                            // 285
    }
    println(x);                                    // 2
    return 0;
}
```

`T*` admite `*p`, `p[i]`, `p->campo`, `p + n`, comparaciones y `(T*)` entre tipos de puntero.
`void*` es el puntero genérico y `sizeof(T)` da el tamaño en bytes. Las variables de clase ya son
referencias: un `Jugador` se convierte a `void*` con `(void*)j` y de vuelta con `(Jugador)p`.

Un método marcado `memory_unsafe` (como `Intercambiar`) tiene un cuerpo inseguro **y** solo se
puede llamar desde otro contexto `memory_unsafe`, como `unsafe fn` en Rust.

## Llamar a C

```faset
static class LibC
{
    public static extern int printf(byte* format, ...);
    public static extern int strlen(byte* s);
    public static extern void qsort(void* data, ulong count, ulong size, delegate*<void*, void*, int> compare);
}

memory_unsafe int CompararInt(void* a, void* b) => *(int*)a - *(int*)b;

int main()
{
    memory_unsafe
    {
        LibC.printf("printf nativo: %d + %d = %d\n".Ptr, 2, 3, 2 + 3);
        println(LibC.strlen("hola".Ptr));          // 4

        int* v = new int[4];
        v[0] = 4; v[1] = 1; v[2] = 3; v[3] = 2;
        LibC.qsort((void*)v, 4, (ulong)sizeof(int), &CompararInt);   // callback de Faset
        println(v[0]);                             // 1
    }
    return 0;
}
```

- `extern` declara una función que existe en C con ese mismo nombre; `...` permite funciones
  variádicas. Declararla no exige contexto (su firma puede usar punteros), pero llamarla sí.
- `s.Ptr` da el `byte*` de una cadena. Los literales terminan en `'\0'`; para una cadena
  cualquiera usa `s.ToCString()` (copia terminada en `'\0'`, que recupera el recolector).
- `String.FromCString(p)` crea una vista de una cadena de C.
- El [recolector de basura](/lenguaje/memoria/) no ve la memoria de C: si una biblioteca de C se
  **guarda** un puntero a memoria de Faset (un búfer, un objeto pasado como `void*`) para usarlo
  más tarde, mantén también una referencia en Faset (un campo, una lista) mientras C lo use. Los
  punteros que C solo usa durante la llamada no necesitan nada. La memoria que devuelve C (`malloc`)
  se libera con `Memory.Free`.
- Las bibliotecas se enlazan con `-l` o con `<NativeLibrary Include="..."/>` en el `.fstproj`.

## Envoltorios seguros

Lo habitual es encerrar los detalles nativos en una clase `memory_unsafe` cuya API pública no use
punteros. Quien la usa no necesita `memory_unsafe`; así está escrita la biblioteca estándar
(`List<T>`, `StringBuilder`, `File`…):

```faset
public memory_unsafe static class Terminal
{
    static extern int isatty(int fd);
    public static bool EsInteractiva() => isatty(1) != 0;   // firma sin punteros
}

int main()
{
    println(Terminal.EsInteractiva());   // código seguro: sin memory_unsafe
    return 0;
}
```

## Windows (Win32)

```faset
static class User32
{
    public const uint MB_OK = 0;
    public const uint MB_ICONINFORMATION = 0x40;
    public static extern int MessageBoxA(void* owner, byte* text, byte* caption, uint type);
}

static class Program
{
    static void Main()
    {
        memory_unsafe
        {
            User32.MessageBoxA(null, "Hola desde Faset!".Ptr, "Faset".Ptr, User32.MB_OK | User32.MB_ICONINFORMATION);
        }
    }
}
```

```bash
faset build ventana.fst --target windows --gui -l user32
```

## Structs con la disposición de C

Los `struct` se generan como structs de C con los campos en el orden declarado, así que puedes pasar
punteros a ellos a APIs nativas. FasetStudio declara de esta forma todos los bindings de Vulkan
(`studio/src/Gfx/Vk.fst`), sin ninguna capa intermedia.

## Exportar funciones

`[Export("nombre")]` publica una función con un nombre de símbolo C concreto, por ejemplo para una
biblioteca que cargará otro programa, o para `JNI_OnLoad` en Android:

```fst
static class Api
{
    [Export("faset_sumar")]
    public static int Sumar(int a, int b) => a + b;
}
```

```bash
faset build api.fst --shared -o libapi.so
nm -D libapi.so | grep faset_sumar      # T faset_sumar
```

## Ver el C generado

`faset emit-c archivo.fst -o salida.c` muestra exactamente qué se genera; `faset build --keep-c`
conserva el C junto al ejecutable.
