# Seguridad de memoria

<p className="lead">
  Faset es <strong>seguro por defecto</strong>. El código normal al estilo C# (clases, <code>new</code>,
  <code>List&lt;T&gt;</code>, <code>string</code>, genéricos, propiedades, <code>ref</code>/<code>out</code>, <code>T&amp;</code>,
  punteros a función) se escribe sin anotaciones. Lo que puede corromper la memoria solo se permite
  dentro de un contexto <code>memory_unsafe</code>, así que siempre se ve dónde vive el código peligroso.
</p>

La seguridad tiene tres capas:

1. **La memoria es automática**: un [recolector de basura](/lenguaje/memoria/) recupera los objetos
   que nadie usa y `delete` nunca libera memoria, así que no puede haber referencias colgando,
   liberaciones dobles ni usos después de liberar.
2. **Al compilar**: siete reglas impiden usar punteros y código nativo fuera de `memory_unsafe`, y
   no se puede devolver una referencia `T&` a una variable local.
3. **Al ejecutar**: el código generado comprueba **siempre**, también en Release, referencias nulas,
   índices de cadenas, divisiones enteras por cero y punteros a función nulos. Las operaciones que
   en C son comportamiento indefinido tienen en Faset un resultado definido.

En el código seguro (sin `memory_unsafe`) quedan descartados los punteros colgantes, la doble
liberación, el uso después de liberar, los accesos fuera de límites y la memoria sin inicializar.

## Las siete reglas

Fuera de un contexto `memory_unsafe` es un **error de compilación**:

| # | Regla | Ejemplos |
|---|---|---|
| 1 | Declarar o usar tipos puntero | `int*`, `void*`, `List<int*>` en variables, campos, parámetros, retornos, conversiones o argumentos genéricos |
| 2 | Cualquier expresión cuyo valor sea un puntero | `&x`, `s.Ptr`, `lista.Data`, `new T[n]`, `Memory.Alloc(...)` |
| 3 | Acceder a memoria a través de un puntero | `*p`, `p->x`, `p[i]` (sin comprobación de límites) |
| 4 | La aritmética de punteros | `p + 1`, `p++`, `p += n` |
| 5 | Reinterpretar referencias | `(Otra)objeto`, `(void*)obj`, conversiones entre punteros a función |
| 6 | Llamar a funciones `extern` (C, Win32, NDK…) o tomar su dirección | `LibC.printf(...)` |
| 7 | Llamar a métodos marcados `memory_unsafe` | todo `Memory.*`, tus propias API peligrosas |

El mensaje indica la línea y cómo arreglarlo (se informa una vez por línea):

```text
programa.fst:12:13: error: desreferenciar un puntero ('*') requiere un contexto memory_unsafe
(usa 'memory_unsafe { ... }' o marca el método o la clase con 'memory_unsafe')
```

La palabra `unsafe` de C# no existe en Faset; usarla da un error que propone la alternativa:

```text
programa.fst:1:14: error: 'unsafe' no existe en Faset; usa 'memory_unsafe' (sustituye 'unsafe' por 'memory_unsafe')
```

## Formas de `memory_unsafe`

De la más precisa a la más amplia:

### Bloque

```faset
int main()
{
    int x = 1;
    memory_unsafe
    {
        int* p = &x;
        *p = 42;
    }
    println(x);                          // 42
    return 0;
}
```

### Método

El cuerpo es `memory_unsafe` **y** el método solo se puede llamar desde otro contexto
`memory_unsafe` (como `unsafe fn` en Rust). Úsalo para API peligrosas:

```faset
memory_unsafe void Rellenar(int* p, int n, int valor)
{
    for (int i = 0; i < n; i++) p[i] = valor;
}

int main()
{
    memory_unsafe
    {
        int* datos = new int[4];
        Rellenar(datos, 4, 7);
        println(datos[3]);               // 7
        delete[] datos;
    }
    return 0;
}
```

### Clase o struct: envoltorios seguros

Una clase `memory_unsafe` tiene una **implementación confiable**: dentro puede usar punteros, pero
sus miembros se siguen usando desde código seguro, salvo los que tienen punteros en la firma (y los
marcados `memory_unsafe`). Así está escrita la biblioteca estándar: `List<T>`, `StringBuilder`,
`File`… son clases `memory_unsafe` con una API pública segura.

```faset
public memory_unsafe class Buffer
{
    byte* datos;
    int tam;

    public Buffer(int n) { datos = new byte[n]; tam = n; }   // a cero; sin punteros: el recolector no lo recorre

    public int Length => tam;
    public byte Get(int i) { if (i < 0 || i >= tam) panic("Buffer: índice fuera de rango"); return datos[i]; }
    public void Set(int i, byte v) { if (i < 0 || i >= tam) panic("Buffer: índice fuera de rango"); datos[i] = v; }
}

int main()
{
    auto b = new Buffer(16);             // código seguro: sin memory_unsafe
    b.Set(3, 200);
    println(b.Get(3));
    return 0;
}
```

### Namespace, archivo y proyecto

```fst
memory_unsafe namespace Bindings { ... }      // todo lo declarado dentro del namespace

memory_unsafe;                                // directiva al principio: todo el archivo
```

```fstproj
<PropertyGroup>
  <AllowUnsafe>true</AllowUnsafe>             <!-- todo el proyecto (o faset build --allow-unsafe) -->
</PropertyGroup>
```

`<AllowUnsafe>` y `--allow-unsafe` sirven para portar código antiguo de golpe; para código nuevo es
mejor marcar solo lo necesario.

### Funciones `extern`

Declarar una función `extern` no requiere contexto (su firma puede usar punteros), pero llamarla
sí. Consulta [interoperabilidad con C](/lenguaje/interop/).

## Referencias a variables locales

Una referencia `T&` devuelta por un método debe apuntar a algo que siga existiendo después de la
llamada. Devolver una referencia a memoria local es un **error de compilación**:

```fst
struct Punto { public int X, Y; }

int& MalCampo() { Punto p = new Punto(); return p.X; }   // campo de un struct local
int& MalParametro(int v) { return v; }                     // parámetro por valor
int& Primero(ref int a) { return a; }
int& MalLlamada() { int x = 1; return Primero(ref x); }   // 'ref' a una local a través de una llamada
```

```text
programa.fst:3:42: error: no se puede devolver una referencia a la variable local 'p' (dejaría de existir al salir del método)
programa.fst:4:28: error: no se puede devolver una referencia a la variable local 'v' (dejaría de existir al salir del método)
programa.fst:6:32: error: no se puede devolver una referencia a la variable local 'x' (dejaría de existir al salir del método)
```

Sí se pueden devolver referencias a campos `static`, a campos de objetos de clase (viven en el heap
del recolector) y a parámetros `ref`:

```faset
class Contador { public int Valor; }

static class Global { public static int Total; }

int& Campo(Contador c) => c.Valor;
int& Estatico() => Global.Total;
int& Mismo(ref int x) => x;

int main()
{
    auto c = new Contador();
    Campo(c) = 5;
    Estatico() = 7;
    int n = 1;
    Mismo(ref n) = 9;
    println(c.Valor + Global.Total + n);   // 21
    return 0;
}
```

## Sin comportamiento indefinido

Faset genera C, pero no hereda su comportamiento indefinido: las operaciones que en C pueden hacer
cualquier cosa tienen en Faset un resultado fijo, igual en Debug y en Release.

| Operación | En Faset |
|---|---|
| Desbordamiento de enteros con signo | aritmética modular (`int.MaxValue + 1 == int.MinValue`) |
| Desplazamientos `x << n`, `x >> n` | el contador se enmascara como en C#: `n & 31` (o `n & 63` en `long`/`ulong`); `<<` sobre negativos está definido |
| Conversión de real a entero | se satura: `(int)1e20 == 2147483647`, `(int)NaN == 0`, `(byte)300.7 == 255` |
| División entera por cero, `int.MinValue / -1` | `Faset panic` (siempre) |

```faset
int main()
{
    double grande = 1e20;
    double nan = 0.0 / 0.0;
    double d = 300.7;
    int uno = 1;
    println((int)grande);            // 2147483647
    println((int)nan);               // 0
    println((byte)d);                // 255
    println(uno << 33);              // 2: 33 & 31 == 1
    println(int.MaxValue + uno);     // -2147483648
    return 0;
}
```

## Comprobaciones en ejecución

Lo que no se puede demostrar al compilar se comprueba al ejecutar. Estas comprobaciones están
**siempre activas**, también en Release:

| Comprobación | Qué detecta |
|---|---|
| Referencias nulas | `obj.Campo`, `obj.Metodo()`, propiedades e indexadores sobre una referencia `null` |
| Índices de cadenas | `s[i]` fuera de `0..s.Length-1` |
| División entera | `/`, `%`, `/=` y `%=` por cero, y `int.MinValue / -1` |
| Punteros a función | llamada a través de un `delegate*` nulo |

Los límites de `List<T>`, `Span<T>`, `Queue<T>`, `Dictionary.Get`, `Substring`… también se
comprueban siempre.

### Diagnósticos de Debug

Con el recolector, `delete` solo ejecuta el destructor y nunca libera memoria, así que usar un objeto
después de `delete` no puede corromper nada. Aun así suele ser un error del programa, y en Debug se
detecta:

| Diagnóstico | Qué detecta |
|---|---|
| Uso después de `delete` | acceder a un campo o método de un objeto al que ya se le hizo `delete` |
| `delete` doble | hacer `delete` dos veces del mismo objeto |

| Configuración | Por defecto | Cambiarlo |
|---|---|---|
| `Debug` | activos | `--no-checks` o `<RuntimeChecks>false</RuntimeChecks>` |
| `Release` | desactivados | `--checks` o `<RuntimeChecks>true</RuntimeChecks>` |

`<RuntimeChecks>`, `--checks` y `--no-checks` solo controlan estos diagnósticos: las comprobaciones
de la tabla anterior no se pueden desactivar. Cuando los diagnósticos están activos se define el
símbolo `RUNTIME_CHECKS`, que puedes usar en [`#if`](/lenguaje/compilacion-condicional/).

```bash
faset build -c Release --checks     # Release con los diagnósticos de 'delete'
faset run --no-checks               # Debug sin ellos
```

### Qué pasa cuando una comprobación falla

El programa escribe en la salida de error y termina con el **código 101**:

```faset
using std.collections;

class Nodo { public int Valor; }

int main()
{
    Nodo n = null;
    println(n.Valor);                    // termina aquí (también en Release)
    return 0;
}
```

```text
$ faset run programa.fst
Faset panic: referencia nula (null): el objeto no existe at programa.fst:8
$ echo $?
101
```

Otros mensajes reales: `división entera por cero`, `índice fuera de rango: 3 (longitud 3)`,
`List: índice fuera de rango` y, en Debug, `uso de un objeto después de 'delete'` y `'delete' doble:
el objeto ya se había liberado`.

Con `FASET_PANIC_ABORT=1` el programa llama a `abort()` en lugar de salir, para depurar con gdb o
generar un volcado de memoria.

### `[TrackCaller]`: la línea de tu código

La línea que se informa es la de **tu** código, no la de la biblioteca. Los métodos con
`[TrackCaller]` (como `panic`, `assert` o `List.operator[]`) reciben la ubicación de quien los llama.
Puedes usarlo en tus propias funciones de validación:

```faset
[TrackCaller]
void Exigir(bool condicion, string mensaje)
{
    if (!condicion) panic(mensaje);
}

int main()
{
    Exigir(1 + 1 == 2, "la aritmética falla");
    return 0;
}
```

Si `Exigir` falla, el mensaje dice `at programa.fst:<línea de la llamada>`, no la línea del `panic`.

## Lo que no cubre

### Carreras de datos

La garantía de Faset con varios hilos es como la de Go. Un `string` es un par (puntero, longitud):
si dos hilos escriben la **misma variable** `string` a la vez sin un cerrojo, otro hilo puede leer
el puntero de una y la longitud de la otra. Protege el estado mutable compartido con `Mutex` y las
demás primitivas de [`std.thread`](/std/thread/). Una carrera sobre un número o una referencia da un
valor u otro, pero nunca deja una referencia colgando.

### Referencias a elementos de una `List<T>`

Una referencia `T&` (o un parámetro `ref`) a un elemento de una `List<T>` apunta al búfer interno
de la lista. Si la lista crece mientras la usas, la lista pasa a otro búfer y la referencia sigue
apuntando al anterior: es memoria válida (el recolector la mantiene viva), pero lo que escribas ahí
ya no se ve en la lista. Toma la referencia después de añadir elementos.

### Código `memory_unsafe`

Dentro de `memory_unsafe` (punteros crudos, funciones `extern` de C) la responsabilidad es tuya: un
`p[i]` fuera de límites o un puntero a memoria de C ya liberada no se comprueban. Para encontrar esos
errores usa [`faset build --sanitize`](/lenguaje/memoria/#detectar-errores) (AddressSanitizer +
UndefinedBehaviorSanitizer).
